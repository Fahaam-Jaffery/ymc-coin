# YMC Brand Strategy

**Status:** Working draft v0.1 · 29 October 2026  
**Decision status:** Strategic direction approved by project owner; identity and name are not final.

## 1. Foundation

### Confirmed project intent
- Payments is the primary category.
- Builders and developers are the primary audience.
- Intended architecture is a Layer 2 built on existing blockchain infrastructure.
- Intended token role combines payments with wider ecosystem utility.
- The name “Yuaan Musk Coin” is open for exploration; YMC remains a working ticker.

### Not yet established
No chain, rollup stack, bridge design, sequencer model, token standard, security mechanism, fee model, throughput, finality, contract audit, launch date, or legal status has been confirmed. Do not describe these as live capabilities.

## 2. Positioning

**Working positioning statement:**  
YMC is a payments-focused blockchain project exploring Layer 2 infrastructure and token utility for builders creating more useful digital payment experiences.

**Core idea:** Payments infrastructure for what’s next.

**Supporting message:** Build better payment experiences.

**Audience:** Developers, technical founders, ecosystem partners, and eventually end users who need understandable, usable digital payment experiences.

## 3. Brand pillars

1. **Built for builders** — clear documentation, integration-first thinking, and honest technical detail.
2. **Payments with purpose** — explain real user problems and payment flows before making performance claims.
3. **Open by design** — describe compatibility and interoperability only when the implementation is defined and verified.
4. **Trust through clarity** — distinguish what is live, in development, planned, and undecided.

## 4. Visual identity — proposed

### Concept
A modern developer-focused payments brand: dark technical surfaces, crisp typography, precise grids, connected-path motifs, and restrained electric accents. Avoid generic coin clip-art, excessive glow, and visual claims of an operational network.

### Palette tokens
| Token | HEX | Intended use |
|---|---|---|
| Midnight | `#0B1020` | Main background |
| Panel | `#111A2E` | Cards and secondary surfaces |
| Electric blue | `#168BFF` | Primary actions and links |
| Digital teal | `#00D5C8` | Secondary accent and active states |
| Ice white | `#F3F6FC` | Main text |
| Slate | `#9AA8BD` | Supporting text |
| Border | `#26344D` | Dividers and outlines |

Use teal sparingly. Check contrast for all interactive states before shipping; do not communicate status by color alone.

### Typography — proposed
- **Display:** Space Grotesk, bold/semibold for headlines.
- **Body/UI:** Inter, regular/medium for body text and interfaces.
- Use tabular numerals for token amounts and data; keep body copy comfortably readable.
- Verify font loading and fallback behavior in implementation.

### Logo direction
The current draft mark is a geometric Y path with blue and white segments. It is a starting concept, not final artwork. Test at 16px, 24px, 32px, monochrome, light backgrounds, and on-chain token icon sizes. Commission/review vector refinements before formal adoption.

### Graphic language
- Flow lines and connected nodes as abstract metaphors, not technical diagrams.
- Grid systems, generous spacing, thin borders, and high-contrast type.
- Use diagrams for architecture only after engineers validate the actual design.
- Use human-readable interface mockups only when clearly labeled as concepts.

## 5. Voice and messaging

**Voice:** Clear, thoughtful, builder-first, optimistic without hype.

**Prefer**
- “Designed to explore…”
- “Our current direction is…”
- “Architecture under evaluation”
- “Read the technical plan”
- “Help shape the builder experience”

**Avoid until verified**
- “Instant,” “zero fees,” “unhackable,” “most secure,” “millions of TPS,” guaranteed returns, guaranteed airdrops, or confirmed exchange listings.
- Implying association, endorsement, or affiliation with any public figure.
- Countdown timers and artificial scarcity before a real, approved launch date.

## 6. Naming workstream

The current name contains “Musk,” which may create confusion or imply an association. Before using it publicly, conduct professional trademark/legal review and check domain, social handle, app-store, ticker, and relevant crypto-project availability. No availability checks are represented as completed here.

Explore names in these territories:
- **Payments-first:** short names suggesting flow, transfer, or settlement.
- **Infrastructure-first:** names suitable for developer tooling and a protocol.
- **Independent master brand:** distinctive invented word, with “YMC” retained only if available and suitable.

Do not finalize the brand name or ticker based only on brainstormed candidates.
